- Signed-in members can play on one device and control it from the web or the phone. Other
  devices show that playback and can pause, seek, skip, or move it. Routes live under
  `/account/playback`. Set `PLAYBACK_PRESENCE_LEAVE_GRACE_MS` (base `api.env` uses 5000)
- A live item a feed drops is stored as ended. Players show Live, time behind live, and rewind
  only when the stream keeps a window. Pause resumes inside that window or jumps to live. An
  ended livestream is not restored, and starting one no longer keeps the last episode's length.
  On the web, Play works again in a signed-in tab that is not actually playing elsewhere
- Podroll, remote items, and Not Yet Added albums return stored remote stubs instead of a live
  Podcast Index lookup. New reads: `GET /remote-item/channel/:idOrIdText`,
  `POST /account/add-by-rss/remote-item/lookup`, and `.../resolve`. Management can re-check,
  re-point, promote, or delete a stub. App migration `0002_remote_stubs.sql`. Leave
  `PARSER_ADD_REMOTE_ITEMS_TO_MQ` empty for stubs (`true` queues a full parse and writes none)
- Browse Top for podcasts, episodes, clips, playlists, and profiles returns only rows with
  listens in that range. Livestream Top, Subscribed Top, and a show's episode Top still include
  zero counts. Public playlists add `GET /playlist/public/recent`. Web and mobile Browse open on
  Top for the past week
- Notifications stay one line with artwork and a relative time. Unseen inbox dots last for the
  visit. A new browser or phone asks once to allow push. A show's notifications still turn on if
  push is declined. Settings warn when this device cannot receive push. Test pushes run only
  where `NOTIFICATIONS_TEST_PUSH_ENABLED=true`
- Operators, first boot of 5.6.0: drop and recreate the database. Bootstrap applies
  `0001_app_schema.sql` and `0001_management_schema.sql`. Existing databases then run app
  migration `0002_remote_stubs.sql`. Set `API_EXPECTED_MIGRATION_FILENAME` to that file and
  `MANAGEMENT_API_EXPECTED_MIGRATION_FILENAME` to `0001_management_schema.sql`. Rename the
  popularity agreement env vars to `TASTE_PROFILE_AGREEMENT_VERSION` and
  `NEXT_PUBLIC_TASTE_PROFILE_AGREEMENT_VERSION` (default `2026-10-21`). Remove
  `AUTH_JWT_EXPIRATION`, `AUTH_MOBILE_ACCESS_TOKEN_EXPIRATION`,
  `AUTH_MOBILE_REFRESH_TOKEN_EXPIRATION`, and `NEXT_PUBLIC_SIDEBAR_GROUP_ORDER`. Session length
  is `AUTH_SESSION_IDLE_EXPIRATION` (31536000). Access tokens are `AUTH_ACCESS_TOKEN_EXPIRATION`
  (900). Listen records are kept `STATS_TRACK_EVENT_RETENTION_DAYS` (90). After the wipe,
  recreate the management superuser and billing rows. `BILLING_SANDBOX_GRANT_ALL=true` grants
  Premium for every sandbox purchase on a test deployment only
