- Playlist owners can save tags on create and edit. The API allows `PLAYLIST_TAG_MAX_PER_PLAYLIST`
  tags (empty means 5) and `PLAYLIST_TAG_NAME_MAX_LENGTH` characters (empty means 50). A longer list
  or name is rejected. A character value above 50 keeps the API from starting. The count can be
  higher than 5. Omitting tags on edit leaves them. List and detail payloads include `tags` as
  folded names, in the owner's order. Public and unlisted playlists include them for anyone who can
  see the playlist. A private playlist includes them for the owner and omits the key for everyone
  else. `GET /playlist/tag?q=` returns up to 10 public tag names that start with the query. Public
  recent and top lists take an optional `tag` (`GET /playlist/public/recent`,
  `GET /playlist/public/top`), applied before paging. An unknown tag is an empty page. Web and the
  phone show the tags on the playlist and on list rows, and public lists can filter by one tag.
  Create and edit on both can add and remove tags. The phone remembers the Browse tag on the
  device. Signed-out `/playlists` opens Public / Recent unless a sort is saved or in the URL.
  `NEXT_PUBLIC_PLAYLISTS_DEFAULT_SORT` and `NEXT_PUBLIC_PLAYLISTS_DEFAULT_RANGE` can open that
  page on Top.
  `NEXT_PUBLIC_PLAYLISTS_DEFAULT_TYPE` (`private`, `private_followed`, or `public`; blank keeps
  signed-in My Playlists and signed-out Global) and `NEXT_PUBLIC_PLAYLISTS_DEFAULT_MEDIUM` (`all`,
  `av`, or `music`) set the opening type and medium when nothing is saved and the URL does not name
  one. Browse playlists does not read those keys. `NEXT_PUBLIC_PLAYLISTS_DEFAULT_TAG` is the opening
  tag on `/playlists` only. App migration `0023_playlist_tag.sql`.
