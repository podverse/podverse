# CarPlay — Simulator browse+play manual checklist (operator)

**Master step:** 12.18 (checklist). **Audience:** operator / QA.
**Ship bar for this checklist:** match **today’s Android Auto scaffold** — browse **Library** +
**Downloads** from the native cache and play through the shared engine with the phone app
**force-quit** (JS dead). Not the later Podcasts/Music/Queue/History UX-parity redesign.

**Prerequisites (all done in code):**

- Apple **CarPlay audio** entitlement granted; provisioning profile includes it — see
  [`CARPLAY-ENTITLEMENT.md`](./CARPLAY-ENTITLEMENT.md). Without this, Simulator will not treat the
  app as a CarPlay audio app.
- CarPlay scene + templates landed (12.7–12.10 at AA-parity scope): `PodverseCarPlaySceneDelegate`
  builds Library + Downloads from `PodverseNativeCache` and plays through `PodverseAudioEngine.shared`.
- App Group wired: `PodverseNativeCache.appGroupIdentifier == "group.com.podverse.app.next"` and
  the CarPlay `ios.entitlements` are in `app.config.ts` (regenerated by `npm run mobile:prebuild`).
  There is deliberately **no** `UIApplicationSceneManifest` — CarPlay + the phone window scene are
  wired dynamically in `AppDelegate` via [`plugins/withPodverseCarPlay.js`](../../plugins/withPodverseCarPlay.js)
  (see §0). The cache now lives in the **App Group container**, not Application Support.

## 0. Phone launch sanity (iOS 26 scene-adoption regression guard)

The CarPlay integration makes `AppDelegate` implement
`application:configurationForConnectingSceneSession:options:` (via
[`plugins/withPodverseCarPlay.js`](../../plugins/withPodverseCarPlay.js)). On **iOS 26** UIScene is
mandatory, and merely implementing that method routes the **phone** window through a
`UIWindowScene` too. Two ways this branch breaks the phone launch (both = black screen / crash,
Metro shows an Android bundle but no iOS bundle):

1. **Super dispatch** — calling `[super application:configurationForConnectingSceneSession:options:]`
   raises an unrecognized-selector `SIGABRT` at launch. `RCTAppDelegate` does not implement it, and
   `[super respondsToSelector:]` is evaluated against `self` (which does), so it cannot guard it.
2. **Bare Default Configuration (no delegate)** — RCTAppDelegate creates `self.window` in
   `didFinishLaunchingWithOptions` before any scene exists, so with no phone scene delegate the
   window is never attached to the scene → `RCTKeyWindow()` nil → **black screen**.

The phone branch must therefore return a Default Configuration whose `delegateClass` is
**`PodversePhoneSceneDelegate`**, and that delegate's `scene:willConnectToSession:options:` must
re-attach the existing `AppDelegate.window` to the `UIWindowScene` and call `makeKeyAndVisible`
(and forward `openURLContexts` for deep links). This is a **native** change — reapply via
`npm run mobile:prebuild` or rebuild the app; a Metro/JS reload alone will not pick it up.

- [ ] Cold-launch the phone app on the iOS Simulator and confirm it reaches the JS UI (no black
      screen, no `Abort trap: 6` / `doesNotRecognizeSelector` crash; check
      `~/Library/Logs/DiagnosticReports/PodverseNext-*.ips` if unsure, and confirm **Mobile Metro**
      logs an `iOS Bundled … index.js` line).
- [ ] The CarPlay branch (role `CPTemplateApplicationSceneSessionRoleApplication`) still returns the
      `PodverseCarPlay` scene with `PodverseCarPlaySceneDelegate` — the two scenes stay independent,
      and app-closed CarPlay does not depend on the phone scene.

## 1. Seed the native cache (phone app, once)

On the booted iOS Simulator (`"iPhone 17 Pro"` or your usual manual device):

1. Install/run the dev client; open the phone UI once.
2. Follow at least one podcast / playlist (writes `library-browse-index.json`).
3. Download at least one episode (writes `downloads-index.json`).
4. Start playing something so a queue snapshot is written (`queue-snapshot.json`).

Confirm the cache files. The App Group is wired, so the cache lives in the **shared group
container** (`group.com.podverse.app.next`), not Application Support:

```bash
# App Group container on the booted simulator (native-cache/*.json live here)
find ~/Library/Developer/CoreSimulator/Devices/$(xcrun simctl list devices booted | rg -o '[0-9A-F-]{36}' | head -1)/data/Containers/Shared/AppGroup \
  -type d -name native-cache 2>/dev/null -exec ls -la {} \;
```

If you see no group container yet, confirm `npm run mobile:prebuild` picked up the entitlements and
the phone app wrote at least once after this build.

## 2. Force-quit the phone app (JS dead)

Swipe the app away from the app switcher so the RN/JS runtime is not running. Do **not** leave
Metro as a substitute for “app open” — the CarPlay scene must not depend on JS.

## 3. Open CarPlay Simulator

1. Ensure Simulator has CarPlay enabled if needed:

```bash
defaults write com.apple.iphonesimulator CarPlay -bool YES
```

Then quit and relaunch Simulator if you changed the default.

2. Boot the device that has the app installed.
3. In Simulator menu: **I/O ▸ External Displays ▸ CarPlay** (wording may be **Hardware ▸ External
   Displays ▸ CarPlay** on older Xcode).
4. Confirm Podverse appears on the CarPlay Home screen and opens without launching the phone UI.

## 4. Watch native logs

In Xcode (or Console.app), filter for native-cache / CarPlay logs. Expect on connect, before any JS:

- `[native-cache] debugDump queue=present(...) downloads=present(...) libraryBrowse=present(...)`
  (logged by `PodverseCarPlaySceneDelegate` on scene connect, JS not running)
- On selecting a download: audio starts and Now Playing appears (no `[carplay] ... soft-fail` /
  `play failed` line, which would indicate an unresolvable URL or load error)

## 5. Browse acceptance (app never opened)

- [ ] Root shows **Library** and/or **Downloads** (a node absent only when its cache is empty) —
      same IA as current Android Auto unless the agent documented a temporary difference.
- [ ] **Library** lists followed podcasts / playlists from the cache.
- [ ] **Downloads** lists downloaded episodes as **playable** items.

## 6. Play acceptance (app never opened)

- [ ] Play a **Downloads** item → audio starts from local `file://` (no network required).
- [ ] Play a streamed item when present in cache with a remote `mediaUrl` → audio starts (soft-fails
      with a log, no crash, if a download has no local path and no remote URL).
- [ ] Now Playing (`CPNowPlayingTemplate`) shows the item **title** (artwork is deferred — CarPlay
      needs a `UIImage`, not a URL; content parity with the Android Auto scaffold).
- [ ] Play / pause / skip / scrub work from CarPlay.
- [ ] One shared engine (lock screen / Control Center reflect the same playback; no second player or
      command center).

## Fallback when CarPlay Simulator cannot show the app

If the app never appears on the CarPlay Home screen:

1. Re-check entitlement + provisioning profile (`CARPLAY-ENTITLEMENT.md`).
2. Confirm the built app's `Info.plist` has the CarPlay scene (`UIApplicationSceneManifest` →
   `PodverseCarPlaySceneDelegate`) — run `npm run mobile:prebuild` and re-check if missing.
3. As an interim signal only, use the **file-level** cache proof:
   [`NATIVE-CACHE-SPIKE-IOS.md`](./NATIVE-CACHE-SPIKE-IOS.md) (container `cat` with Metro not
   attached). That is **not** a substitute for this checklist’s browse+play gate.
