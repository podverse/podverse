### Step 02 — area A

- **Plan 10.** Catalog plus assignment tables. The alternative was a jsonb array on `playlist`.
- **Plan 10.** Only the folded name is stored. The alternative was keeping the typed casing.
- **Plan 10.** 50 characters and 5 tags. Length uses the existing short varchar. Five is the request's cap.
- **Plan 10.** Free text after trim, whitespace collapse, and case-fold. The alternative was a slug alphabet.
- **Plan 10.** A name that no playlist still uses is removed when the save commits. The alternative was keeping every name that had ever been saved.
- **Plan 11.** A sixth tag is rejected. Blanks are dropped. A repeated name keeps the first copy.
- **Plan 11.** An edit that omits `tags` leaves them. A present array, including an empty one, replaces them. The alternative was requiring `tags` on every edit.
- **Plan 11.** A name is inserted only inside playlist create or update. Also plan 12.
- **Plan 11.** Public and unlisted playlists always include `tags`. A private playlist includes it for the owner and omits the key for everyone else. The alternative was sending an empty array when the tags are hidden.
- **Plan 12.** Search is public, a prefix, at most 10 names, and it hides names that exist only on private playlists. The alternative was also returning the caller's private-only names, or matching the middle of a name.
- **Plan 13.** The public filter is one exact `tag`, applied before paging. A blank value does not filter. An unknown name is an empty page.
- **Plan 13.** Public top still omits a playlist whose count for that range is zero.

### Step 03 — area B

- **Plan 21.** A new name joins the form's tag list on Enter, on the create row, and on blur. It is still only stored when the playlist is saved. The alternative was Enter only, or existing names only.
- **Plan 21.** The tag face uses Chip's filter metrics (`--border-radius`, border, secondary background). The alternative was the fully round pill.
- **Plan 21.** Backspace does not remove the last tag. The alternative was removing it when the field is empty.
- **Plan 21.** `maxCount` is a prop. The playlist form passes 5. The alternative was hard-coding 5 in the control.

- **Plan 21.** Read-only with no tags renders nothing. The alternative was an empty field shell.
- **Plan 20.** The suggestion list is a combobox: focus stays in the field, and the highlighted row is `aria-activedescendant`. The menu uses FormDropdown's colors, border, and radius. The alternative was moving focus through menu items.
- **Plan 20.** Search waits 450ms. The alternative was SearchInput's 1000ms wait.
- **Plan 20.** The field has no magnifying glass. The alternative was copying SearchInput's icon.
- **Plan 20.** Enter in the field does not submit the surrounding form. The alternative was letting Enter submit the playlist form.
